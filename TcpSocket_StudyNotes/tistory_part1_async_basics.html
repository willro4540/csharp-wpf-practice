1부. 서버 코드를 보기 전에 — "비동기(async/await)"가 대체 뭔데?

먼저 하나만 짚고 갈게요. "코드"라는 건 컴퓨터한테 순서대로 시킬 일을 적어놓은 목록이에요. 요리 레시피랑 똑같아요 — "1. 물을 끓인다 2. 면을 넣는다 3. 3분 기다린다" 이런 식으로요. 이번 글엔 코드가 몇 줄 나오는데, 코드를 몰라도 옆에 있는 그림과 설명만 보셔도 이해되게 썼어요. 코드는 "아 이렇게 생겼구나" 정도로만 보고 넘어가셔도 돼요.

지난 시간에 TcpListener, TcpClient라는 이름을 처음 봤어요. 근데 그 전에 코드 안에 async, await라는 낯선 단어부터 나와서 막막했을 거예요. 오늘은 네트워크 얘기는 잠깐 미뤄두고, 이 단어들이 대체 왜 필요한지부터 완전히 처음부터 풀어볼게요.

1. 클래스랑 메서드, 다시 한 번 (진짜 기초)

C#을 오랜만에 보면 이것부터 헷갈려요. 아주 짧게 복습만 하고 갈게요.

class Dog
{
    public string Name;          // 이건 "필드" — Dog가 가지고 있는 정보

    public void Bark()           // 이건 "메서드" — Dog가 할 수 있는 행동
    {
        Console.WriteLine(Name + "가 짖습니다!");
    }
}

이렇게 설계도(class)를 그려놓고, new Dog()라고 하면 실제로 강아지 한 마리(객체/인스턴스)가 만들어져요. 그 강아지한테 .Bark()라고 하면 방금 설계도에 적어둔 행동을 실제로 시키는 거예요.

이번 강의에 나올 TcpListener도 똑같아요. 누군가 미리 만들어둔 "서버 역할을 하는 설계도"고, 우리는 그걸로 객체를 하나 만들어서(new TcpListener(...)) .Start() 같은 메서드를 불러 쓰는 것뿐이에요.

2. 그런데 "스레드"가 정확히 뭔데?

앞으로 계속 나올 단어라서 여기서 확실히 짚고 갈게요. 스레드(Thread) = 실제로 일을 하나씩 처리하는 "일꾼"이에요. 컴퓨터 안에서 "지금 이 순간 이 작업을 실행하고 있는 주체"를 말해요.

식당 비유로 보면: 요리사가 딱 한 명이면, 그 요리사가 손님 응대도 하고 요리도 하고 계산도 해야 해요. 근데 사람은 한 번에 한 가지 일만 손댈 수 있죠. 우리 프로그램도 보통 이런 "일꾼" 하나(또는 소수)가 모든 일을 순서대로 처리해요.

이제부터 "스레드가 자리를 비운다/묶여있다"는 말이 나오면, 이 일꾼이 지금 손이 비어있는지, 아니면 뭔가 붙잡고 못 움직이는지를 말하는 거라고 생각하시면 돼요. 뒤에서 계속 이 그림을 떠올리면서 읽으면 훨씬 쉬워요.

3. 동기(Synchronous) — 우리가 원래 알던 방식

지금까지 짜본 C# 코드는 대부분 이런 식이었을 거예요.

Console.WriteLine("1번");
Console.WriteLine("2번");
Console.WriteLine("3번");

위에서 아래로, 한 줄이 끝나야 다음 줄이 실행돼요. 이게 동기(synchronous)예요. 너무 당연해서 이름 붙일 필요도 없었죠.

문제는 중간에 "오래 걸리는 일"이 끼어있을 때예요. 예를 들어 이런 상황이 있다고 해봐요. (아래는 실제 C# 문법이 아니라, 이해를 돕기 위해 한글로 풀어 쓴 가짜 예시예요)

Console.WriteLine("커피 주문함");
커피를_직접_내린다();  // 이게 3초 걸린다고 하면?
Console.WriteLine("커피 다 됨");

동기 방식에서는 중간 줄이 끝날 때까지 프로그램 전체가 그냥 멈춰서 기다려요. 콘솔 프로그램이면 그냥 3초 느린 정도로 넘어가지만, 화면(UI)이 있는 프로그램(WinForm 같은)에서 이 짓을 하면 큰일 나요 — 3초 동안 창 전체가 하얗게 굳어버려요(마우스 클릭도 안 먹힘, "응답 없음" 상태). 왜냐하면 화면을 그리는 것도, 버튼 클릭을 받는 것도 전부 단 하나의 스레드(작업자)가 담당하는데, 그 스레드가 지금 딴 일 하느라 못 움직이거든요.

4. 비동기(Asynchronous) — "기다리는 동안 다른 일도 하자"

비유를 하나 들어볼게요.

카페 상황
㉠ 동기 방식: 손님이 커피 주문하면, 점원이 커피 다 나올 때까지 그 자리에 서서 기다림. 그동안 다른 손님 주문은 아예 못 받음.
㉡ 비동기 방식: 손님이 주문하면 번호표를 주고, 점원은 바로 다음 손님 주문을 받으러 감. 커피가 다 되면 번호가 불리고, 그때 손님이 와서 가져감.

㉡이 바로 async/await가 하는 일이에요. "이 작업은 시간이 걸리니까, 기다리는 동안 너(스레드)는 다른 일을 해도 돼. 결과가 나오면 그때 다시 불러줄게"라는 뜻이에요. (이것도 개념 설명용 가짜 예시예요 — 실제 문법은 2부에서 진짜 코드로 봐요)

Console.WriteLine("커피 주문함");
await 커피를_직접_내린다();   // 여기서 스레드가 "묶여있지 않고" 풀려남
Console.WriteLine("커피 다 됨");  // 커피가 실제로 다 됐을 때 이 줄이 이어서 실행됨

겉보기엔 순서(1번→2번→3번)가 그대로 유지되는 것처럼 보이지만, await가 붙은 줄에서 "기다리는 동안"에는 스레드가 다른 일(예: 화면 그리기, 다른 버튼 클릭 처리)을 할 수 있어요. 이게 동기 방식과의 결정적인 차이예요.

말로만 하면 헷갈리니까 그림으로 비교해볼게요.

위 그림에서 중요한 건, 비동기 쪽은 A를 기다리는 "동안"에 B, C 주문도 같이 처리됐다는 거예요. A가 커피를 기다리느라 다른 사람 응대가 멈추지 않아요.

비유 하나 더 — 세탁기를 생각해보세요. 세탁기 시작 버튼을 누르고 그 앞에 40분 동안 서서 지켜보는 사람은 없죠. 버튼만 누르고(await 세탁기_돌리기()) 다른 집안일을 하다가, "삐삐" 알림이 울리면(작업 완료) 그때 가서 빨래를 꺼내요. "기다리는 동안 다른 일을 한다"는 감각은 사실 일상에서 이미 익숙한 거예요 — 코드에서는 그걸 명시적으로 await라고 써줘야 할 뿐이에요.

❓ 자주 하는 오해: "async라고 쓰면 여러 작업이 동시에(병렬로) 실행되는 거 아닌가요?"

아니에요. async/await는 "기다리는 동안 스레드를 놀리지 않는다"는 뜻이지, "여러 일을 진짜로 동시에 처리한다"는 뜻이 아니에요. 위 세탁기 비유로 치면, 세탁기가 돌아가는 동안 내(스레드)가 설거지도 하고 청소도 할 수 있다는 거지, 내가 몸이 두 개로 늘어나서 세탁기를 붙잡고 있으면서 동시에 설거지도 하는 게 아니에요. 이 차이가 진짜 "병렬 처리(Parallel)"와 "비동기(Asynchronous)"를 구분하는 핵심인데, 지금 단계에선 "비동기 = 기다리는 동안 스레드를 안 붙잡아둠" 정도만 정확히 알면 충분해요.

5. 규칙 두 가지만 외우면 됨

  1. await는 async라고 표시된 메서드 안에서만 쓸 수 있다. ("나는 기다리는 동안 남 눈치 안 보고 자리 비울 수 있어"라고 미리 선언해두는 것)
  2. 이름이 ~Async로 끝나는 메서드는 대부분 앞에 await를 붙여서 쓴다. (예: AcceptTcpClientAsync(), ReadAsync() — .NET에서 지켜지는 명명 규칙이에요)

6. 그럼 서버는 왜 특히 이게 중요한가?

은행 창구를 생각해보세요. 창구 직원(스레드)이 한 명뿐인데, 손님 A 업무 처리에 5분 걸린다고 "다음 분!"을 안 부르고 그 자리에 가만히 서 있으면, 뒤에 줄 선 손님 B, C, D는 5분 내내 아무것도 못 받아요.

서버도 똑같아요. 손님 A의 접속을 처리하는 동안(대기하는 동안) 손님 B의 접속 요청도 받을 수 있어야 진짜 서버 역할을 해요. 그래서 다음 시간에 볼 TcpListener 서버 코드는 처음부터 끝까지 전부 async/await로 짜여있어요.

오늘 정리

  • 동기: 한 줄씩 순서대로, 오래 걸리는 일이 있으면 전체가 멈춤
  • 비동기(async/await): 오래 걸리는 일을 기다리는 동안 스레드를 풀어줬다가, 끝나면 이어서 실행
  • ~Async로 끝나는 메서드는 await와 짝지어 쓴다
  • 서버는 "여러 손님을 동시에" 상대해야 하니까 비동기가 사실상 필수

넘어가기 전에 하나만 확인해볼게요

요리사(스레드)가 손님 A의 국이 끓기를 기다리는 동안, 손님 B의 주문을 받으러 갔어요. 국이 다 끓으면 어떻게 될까요?

(a) 요리사는 이미 다른 일(B 응대) 하느라 바빠서 국이 끓은 걸 영영 모른다
(b) 국이 끓었다는 신호가 오면, 요리사가 하던 일을 마저 하다가 그 신호를 받아서 다시 국 쪽 작업을 이어서 한다

정답은 (b)예요. await로 넘긴 작업은 "잊혀지는" 게 아니라, 끝나면 "다시 불러달라"는 예약이 걸려있는 상태예요. 그래서 결과가 나오면 정확히 그 지점부터 이어서 실행돼요. 이걸 붙잡고 2부로 넘어가면 훨씬 쉬워요.
